# 大文件性能分析与优化（读取 / 展示 / 渲染 / 打开速度）

> 对标：VS Code、Typora、Mark Text、Obsidian
> 范围：MdEv v0.7.0 → 大文件场景性能治理

## 1. 当前架构与瓶颈定位

| 环节 | 实现 | 大文件问题 |
| --- | --- | --- |
| 读取 | 主进程 `readFile(path,'utf-8')` 一次性读全量，经 IPC 以字符串回传 | 一次性开销，主进程异步不阻塞渲染；多 MB 文件仅首次有成本 |
| 编辑器 | CodeMirror 6（`vue-codemirror` + `basicSetup`） | **已虚拟化**：仅渲染视口内行、按需增量高亮，**非瓶颈** |
| 预览渲染 | `PreviewPane` 监听 `store.content`，**每次按键全文 markdown-it 解析 + 重建整段 DOM** + DOMPurify + Mermaid | **核心瓶颈**：大文件每次按键主线程冻结 |
| 图表 | 每次渲染对所有 `.mermaid` 块串行 `mermaid.render` | 含大量图表的文档长时间阻塞 |
| 自动保存 / 历史 | `historyHandlers.snapshotFile` 每次保存写全量快照 | 超大文件反复写多 MB 副本，占盘 |

**结论**：编辑器本身对大文件友好（CM6 视口虚拟化）。真正的瓶颈是 **预览的全量重渲染**，且发生在主线程、与主线程输入同步。

## 2. 基准（markdown-it 解析耗时，纯解析，不含 DOM/DOMPurify/Mermaid）

| 规模 | 体积 | parse 平均 |
| --- | --- | --- |
| 2k 行 | ~168KB | 12ms |
| 10k 行 | ~840KB | 36ms |
| 50k 行 | ~4.2MB | 203ms |
| 200k 行 | ~16.8MB | 867ms |

实际预览成本更高（DOM 构建 + DOMPurify + 图表，约 2–3×）。即 **4MB 文档原来每次按键会触发 ~200ms+ 的主线程冻结**，17MB 文档 ~1s+，编辑基本不可用。

## 3. 行业对标

- **VS Code**：超大文件进入「大文件模式」，关闭语义高亮/折叠/小地图等重物，状态栏提示；从不整文档阻塞。
- **Obsidian**：预览按区块/懒加载渲染，滚动时增量生成。
- **Typora**：所见即所得单 DOM，但仍依赖增量更新而非全量重排。
- **Mark Text**：基于 CodeMirror，同样面临整文档预览成本，靠防抖缓解。

共通手段：**防抖 / 增量 / 懒加载 / 大文件降级模式**。

## 4. 本次实现的优化

### 4.1 分级预览刷新（`PreviewPane.vue` + `src/core/perf.js`）
- 按字符数 / 行数对文档分级：
  - `normal`（≤60 万字符且 ≤2 万行）：**120ms 防抖**，合并快速输入。
  - `large`（>60 万字符或 >2 万行）：**400ms 防抖**，降低重渲染频率。
  - `huge`（>500 万字符或 >8 万行）：**停止自动刷新**，打开即见内容但不阻塞；编辑期间编辑器保持流畅，预览按需更新。
- 编辑模式（`viewMode==='edit'`）下完全跳过预览渲染，省 CPU。
- 切标签立即渲染；内容未变化则去重跳过。

### 4.2 Mermaid 懒渲染
- 仅渲染视口内（含 300px 预渲染边距）的图表，其余在滚动进入视口时再渲染（`IntersectionObserver`）。
- 含大量图表的文档不再一次性阻塞主线程。

### 4.3 超大文件降级模式 UI
- 状态栏显示文件体积（B/KB/MB）与「大文件 / 超大文件」标识。
- 预览顶部横幅提示「预览已暂停自动刷新」，提供「刷新预览 (Ctrl+Shift+R)」按钮；快捷键 `Ctrl+Shift+R` 强制渲染一次。

### 4.4 历史快照保护
- `historyHandlers.snapshotFile` 对 >2MB 文件跳过快照，避免反复写多 MB 副本占盘。

### 4.5 打开速度
- 超大文件打开时**不强制渲染预览**，编辑器瞬间可用，预览按需刷新，消除打开时的秒级冻结。

## 5. 仍可进一步做的（未本次实施）
- **Web Worker 解析**：将 markdown-it 解析移出主线程，huge 文件也可近实时预览（需将 DOMPurify/highlight.js/插件与源码行注入一并迁入 worker，工作量较大）。
- **预览虚拟滚动**：对超大文档按视口分块渲染（WYSIWYG 场景实现成本高，收益相对有限）。
- **增量解析**：基于行变更做局部重渲染（markdown-it 非增量，需自研 diff 策略）。
- **大文件读取进度 / 超限确认**：对极端体积（如 >50MB）给出确认或只读提示。
